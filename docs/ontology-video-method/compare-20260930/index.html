1. 四条路线各自怎么来的

① 自由生成 无锁定图

只给网关三段英文提示词（首帧 / 末帧 / 运动），GPT-image 自己画两张关键帧，再补间。没有任何参考图。

  1. 写首帧提示词「深空灰 SU7 展厅 无尾翼」
  2. 写末帧提示词「同一台车 同机位 装黑色尾翼」
  3. 网关 → GPT 出两帧 → Seedance 补间

耗时：提交 → 完成约 6 分钟。人工介入：0。

② 锚图本体 本方案 · 生产环境

POST /api/v1/ontology：LLM（claude-sonnet-5）把需求拆成 2 对象 / 1 链接 / 5 锚图 / 3 镜头；锚图以 SU7 身份图为参考逐张编辑；人在审核页选起止锚图后补间。

耗时：起草 ~10s，5 张锚图 ~4 分钟，视频 ~6 分钟。人工介入：审核一次（本次把 LLM 排的「车尾→装尾翼」换成「身份→装尾翼」，才是真同机位）。

③ 3D 白模重绘 blender-story 思路 · 渲染器换成车库

SU7 服务车库 V2.3（Three.js，真车 GLB）同机位截两帧：原车 / 勾选「运动尾翼」；GPT-image 参考重绘成深空灰夜间展厅（第二帧同时参考第一帧成品保持外观一致）；再补间。

耗时：截图 ~20s，两次重绘各 ~40s，视频 ~6 分钟。人工介入：0（脚本驱动车库）。

④ 本体 + Blender 层 新增 · 生产环境

POST /api/v1/ontology 加 render_backend=blender：LLM 除了对象 / 链接 / 锚图，还要产出一层 Blender 层——它本身就是本体的一部分，不含任何 SU7 特定代码：

  • 场景预设：showroom_dark（枚举 4 种）、地面是否反光
  • 主体归一化：资产 su7.glb（worker 模型库里选）、文件 up/forward 轴、真实车长 4.97 m、转台角
  • 状态 = 有界操作：state-spoiler → add_part（尾翼盒 1.4×0.28×0.06 m，贴在 rear-top，射线吸附到后备箱盖表面）
  • 机位语法：每张锚图只写 方位角 / 仰角 / 距离系数 / 焦距 / 看向哪（枚举）。身份图与链接图共用 az145 / el15 / ×1.1 / 35mm，所以两张灰模逐像素同机位

Windows worker 用 Blender 5.2 headless 出灰模，再以「灰模为第一参考、身份图为第二参考」GPT-image 重绘，然后进同一套审核页与补间。

耗时：起草 ~15s，3 张灰模 ~1 分钟，3 张重绘 ~2.5 分钟，视频 ~6 分钟。人工介入：审核一次（本次直接全通过，只改了运动提示）。

4. 结论

  1. ① 不能用在任何需要"这台车"的场景：两帧各画各的，SU7 变成泛化轿车，中途还换了前脸。这就是「自由生成保不住对象同一性」的实证。
  2. ② 和 ③ 都保住了同一性，画质相当。差别在于：③ 的几何是真的（来自 GLB），② 的几何是 GPT-image 参考编辑"像"出来的；② 不需要 3D 资产、人可以在审核页逐张把关，③ 需要车库且重绘环节黑盒。对有 3D 资产的 SU7，③ 是 ② 的"锚图来源升级版"——两者可以合并：车库截图当锚图喂进本体，走同一套审核与出片。对没有 3D 资产的 M9 / ES8，只有 ②。
  3. ①②③ 共同的问题是机位没锁住：Seedance 把 "subtle push-in" 做成大幅推近。④ 复测已给出答案：运动提示改成 "Locked-off static camera, zero camera movement, no zoom, no pan"（并去掉 push-in 字眼）后，dreamina-seedance-2-0 真的把机位钉住了，四个采样帧几乎逐像素一致、只有尾翼长出来。所以推近是提示词问题，不是关键帧来源问题；本体层面已把这句写成「同机位对比」镜头的默认运动提示模板。
  4. ④ 相对 ③ 的增量不在画质，在"机位是数值"：③ 的机位靠人在车库里摆好再截图，换个主体（M9 / ES8 / 一瓶机油 / 一个人形 proxy）就得重摆；④ 的机位是本体里的 5 个有界数字（方位 / 仰角 / 距离系数 / 焦距 / 看向），状态是有界操作（显隐 / 加件 / 旋转 / 平移），场景是 4 个预设——"怎么把 Blender 建好"这件事本身被写进本体，LLM 只填枚举和比例，程序把它变成灰模。没有 GLB 也能用 proxy 盒子先把机位与状态定死。这就是「本体已建模，AI 只填数值」在 3D 侧的落地。
  5. 本体路线本次暴露的产品缺口：LLM 排的"同机位对比"镜头用了车尾锚图→前 3/4 锚图，审核人当时无法改起止锚图，只能绕过。已修：审核页镜头卡片加了起止锚图下拉框，PATCH 接受 start_anchor / end_anchor（待部署）。
