本体视频法：对象、关系、数值与锁定图路线

版本 v0.2 · 2026-09-30 · 麦秋选 一句话：先把场景本体建好（对象 / 关系 / 数值），视频生成时 AI 不画画、不建模，只填有界的槽位；画面由锁定的图片锚点和确定性补间给出。 每一帧都能回溯到本体对象和手册证据。

0. 结论先行

判断 结论
"本体已建模，AI 只填数值"能不能成立 成立。 这正是 SU7 服务车库 V2.3 已跑通的模式：AI 只输出受控 patch，前端按能力表校验，未知 ID 原子拒绝，无 AI 时手动照常用。
"填数值"填什么 填有界枚举和比例，不填裸浮点。 相机坐标、位移这类连续值永远由程序算或由锚图替代。
本体之间的联系怎么进画面 链接不需要新对象类型，一条链接被渲染成三种画面语法之一：同框、先后、脚注。
要不要先建 3D 白模 不必。 把图片当属性值锁死（锚图），视频只做锚图之间的短补间，维修指导线也够用；需要绕零件自由转的镜头以后单独补 3D。

2. 放进已有本体框架：对象 · 属性 · 链接 · 动作

按团队已经在用的本体框架理解（对象类型 → 属性 → 链接类型 → 动作，外加事实来源与复核状态治理字段），视频不引入新范式，只增加几类对象和一种属性类型。

2.1 对象类型

场景层   车辆 Vehicle · 系统 System · 总成 Assembly · 零件 Part
         · 连接 Connection · 工具 Tool · 人物 Actor（技师 / 车主）
动作层   步骤 Step · 动作 Action · 警示 Warning · 证据片段 Evidence
叙事层   镜头 Shot · 段落 Sequence · 旁白 Narration · 字幕 Caption

Shot 相当于 M9 方法里的"场景快照"实例；一次出片相当于一次"判定运行"；每个镜头链接到它引用的证据片段。维护人、指纹、技术复核 / 业务复核状态原样复用。

2.2 属性：数值分三档

档 来源 例子 AI 能否修改
事实属性 手册 / BOM / 数模，带证据 零件包围盒、连接数量、扭矩、适用版本 否
派生属性 由函数按事实属性算出 相机位置、爆炸位移上限、关键帧时间 否
决策属性 实例创建时由人或 AI 填，值域有界 framing（枚举）、duration_s（2–12）、explode_ratio（0–1）、target（必须是已存在的 Part） 是，且只能填这一档

"AI 只填数值"精确地说是：AI 执行一个动作——创建 Shot 实例——这个动作的参数就是第三档属性，值域校验由本体平台做，越界或引用不存在的对象就整个动作失败。这与框架里 Action 带参数、带校验规则、带副作用的定义完全一致。

2.3 链接：联系怎么进画面

链接本身是一等对象，有方向、有基数、自己带属性。视频里同一条链接会被渲染成三种画面语法之一：

链接性质 例子 画面体现
空间 / 结构 part_of、connects_to、fastened_by 同框：目标件入镜时，另一端自动一起进画面——父总成半透明做位置参照，连接点高亮，紧固件亮出来
时序 / 依赖 blocks_removal_of、step_precedes 先后：镜头顺序不是 AI 排的，是从依赖链推出来的——盖板挡着 BMS，那盖板镜头必然在 BMS 之前
引用 / 证据 supported_by、applies_to（版本适用） 脚注：字幕角标、证据页码、"仅适用 XX 版本"水印

链接自带的属性直接变成画面元素：fastened_by 上的 qty=4 就是画面里的 "×4" 标注；torque 有值就出现，为空就不出现——不编。

2.4 一个镜头串起来

AI 创建一个 Shot：target=BMS-01, framing=close, action=remove, duration=4。本体沿链接展开：

  • BMS-01 —fastened_by→ Bolt×4 → 同框高亮 + "×4"
  • Cover-02 —blocks_removal_of→ BMS-01 → 自动在前面插一个拆盖板镜头，之后盖板变半透明
  • BMS-01 —part_of→ 电池包 → 半透明位置参照
  • 该步骤 —supported_by→ E05 → 字幕角标 "E05 p.312"

AI 填的只有那四个参数。

3. 渲染路线：为什么选"锁定图本体"

3.1 三条路线比较

维度 3D 白模 锁定图本体 自由生成（只给提示词）
对象同一性 有 有（锚图约束） 无
关系几何真值 有 关键帧上有，补间过程不保证 无
属性可校验 程序校验 关键帧人工审一次，永久复用 每次人眼看
改槽不改模 有 有（换锚图 ID 重生成一段，其他段不动） 无
任意视角 有 只有锚过的角度 有但不可信
补间可信度 确定 4 秒内一般稳，长镜头中途可能变形 差
前置成本 建模 生图 + 审图 无
复用现有链路 需 headless 渲染器 直接复用生图 + 首尾关键帧图生视频 复用

自由生成保得住内容层（出场对象、顺序、旁白证据），保不住对象同一性和关系几何真值，对维修指导线不够。3D 白模全都保得住，但要先建模，而数模来源本身就是卡点。锁定图本体是中间解：把"连续可算"换成"离散锚定 + 短补间"，丢掉任意视角和补间过程的确定性，换来不建模、不写求解器、直接复用现有链路。

3.2 锁定图本体的定义

把图片本身当成一种属性值，钉死在本体里：

  • 对象 = 身份锚图：一个人 / 一个 BMS 有一张标准像。
  • 属性取值 = 图：angle=front / side / rear-3q、state=installed / loosened / removed、expression=calm / alert、holding=wrench——每个枚举值挂一张锁定图。属性值域有限，图就有限。
  • 链接实例 = 图：BMS —fastened_by→ Bolt×4 这条链接也锁一张"装配好的样子"，关系的几何真值被钉死，不再是提示词。
  • 动作 = 选图：AI 只做一件事——挑起点锚图 ID、终点锚图 ID、时长。相机坐标、爆炸比例被"两张锁定图之间补间"替代。

这与现有 /api/v1/image-videos 首尾关键帧图生视频链路是一回事：首帧 = 锁定的"装好"图，末帧 = 锁定的"拆下"图，视频模型只负责中间几秒的运动。导演台缩成一个选图器。

3.3 关键帧密度决定可信度

一个拆卸动作不要只锚"装好 / 拆下"两张，而是"装好 / 松开 / 取下"三张甚至更多。补间越短，模型幻觉空间越小（螺栓数量中途变化这类问题基本消失）。

3.4 瓶颈挪到"锚图从哪来、谁审"

对象类别 锚图来源 难度
人物、外观件、精品配件 生图 + 多参考图编辑 → 人审一次 → 锁定 低
车内件 维修手册图例本身就是现成锚图：手册线图是"官方认证的对象长相"，直接作锁定图或作生图参考；锚图 ID 与手册页码是同一件事 中，且比 3D 更贴证据链
组合状态（链接实例） 手册分解图 / 装配图 中

组合数要控：不给全部 1,035 个件建锚图，只给当前 SOP 用到的件建，按需扩。生成不贵，审图是瓶颈，所以审过的图必须进本体永久复用。

4. 三条业务线共用一个本体

线 观众 镜头模板差异 锁定图路线能否达到
A 维修指导 / 远程协同 技师、二线专家 近景多、透视上下文、拆序严格、工具出镜、警示前置 够用，前提是关键帧密度够
B 培训课程 新技师、培训部 先整车定位再局部、系统组成图、术语字幕、可分章 概念片与系统总览完全可以；部件级拆装同 A
C 车主 / 展厅 / 精品选配 车主、销售 慢旋转、爆炸炫技、精品试装同机位对比、不出工具不出警示 完全达到

同一套 Part / Connection / 锚图数据，只换镜头模板与旁白风格。

5. 一次出片的流程

  1. 输入：结构化 SOP（步骤 / 要点 / 警示 / 责任人）+ 车型变体 + 目标观众。
  2. 本体检索：步骤里的零件名对齐到 Part.id，拉出连接关系与拆序依赖；缺失即登记"资料缺口"，不编。
  3. AI 填槽：拿到步骤 + 可用 Part / 锚图 / 动作枚举 + 观众对应的镜头模板，输出 Shot 列表 JSON。Schema 校验，未知 ID / 越界值整包拒绝。
  4. 展开：按 blocks_removal_of 补前置镜头；每个 Shot 解析为"起点锚图、终点锚图、时长"。
  5. 生成：首尾关键帧图生视频；无锚图的镜头标记 unanchored，需人工确认后才生成。
  6. 合成：字幕、步骤号、警示牌、证据脚注；旁白仅对 evidence_ids 非空的句子合成语音，无证据的句子只留灰字。
  7. 产物：mp4 + srt + evidence-manifest.json（镜头 → 步骤 → 证据 → 页码）+ shots.json（可回放、可改槽重生成）。
  8. 验收：技术复核（部件、顺序）+ 业务签认（口径），沿用双状态字段。

6. 风险与边界

  1. 锚图是推定还是事实要标清：手册图例来源的锚图标 evidence，生图来源的标 simulated，视频画面带"示意"水印。
  2. AI 选错目标：同名件多配置时强制追问变体，不猜。
  3. 补间幻觉：长于 6 秒的单镜头强制拆成多段锚图。
  4. 旁白幻觉：无证据不发声。
  5. 配额：图生视频每段都消耗额度，先在短 Demo 上验证密度与时长的关系再放量。
  6. 合规：不含 VIN / 用户数据；培训与营销素材分库；外发走既有数据外发流程。

7. 建议的最小 Demo

  • 场景：M9 或 ES8 手册中一个 5 步以内的拆装小节（有现成图例），或 SU7 车库已验证的 BMS 拆卸路线。
  • 锚图：每步 2–3 张，共 10–15 张，其中车内件优先用手册图例。
  • 产出：30 秒视频 + SRT + 证据清单；同一 shots.json 人工换一张锚图重生成一段，证明"改槽不改模"。
  • 验证：技术支持日会上对照 BRD 第 10 条与功能清单待决第 5 项（3D 数模来源与远程可视化 PoC）。
  • 不做：TTS 声库选型、原厂数模接入、AR、C 端上线、3D 建模。
