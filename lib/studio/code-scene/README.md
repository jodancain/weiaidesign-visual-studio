# Declarative story scene runtime

The actual model-authored SceneProgram files are in `output/code-films-20261002/source/*-scene-program.json`. The initial provider outputs are retained in `source/opus-results/` and `*.model-v1.json`. Camera corrections are explicit engineering revisions with parent/content hashes; action timing remains the model-authored timing. The Three.js geometry, deterministic action recipes, compiler and tests are engineering code, not claimed as model-generated source.

`createCodeScene(program)` returns a Three Scene, a current-shot PerspectiveCamera, a map of all shot/saved cameras, exposure, `evaluateFrame(frame, sceneSnapshot?)`, `snapshot()` and `dispose()`. `compileSceneProgram(program)` returns the editable StudioScene snapshot. The director calls exactly the same runtime from `animation.ts`; both export adapters import this module. No remote textures, runtime code evaluation or video model calls occur here.

The closed schema fixes 24fps, 1280×720, ten shots and 1440 frames. Global intervals are end-exclusive. Camera movement and action timing are declarative, while character contact placements are fixed validated recipes. Nonempty `blocking` is rejected. The five identities are four original rigid-jointed SkinnedMesh characters with individual finger bones, plus an articulated mechanical scout hierarchy. Materials include deterministic procedural wood, cloth and painted metal textures. The three environments are real mesh scenes with shadows and lights.

The handwheel grip is solved in world space, the canopy loses two mesh panels and an exactly matching two-triangle patch, the jump crosses a physical ground gap, and the seed changes between lamp, hand and soil without duplication. These are deterministic authored motions, not cloth/rigid-body physics simulations. No narration is produced by this module.

Director edits are overlays: object and part base-transform differences apply to the procedural pose; explicit keyframe tracks apply absolute transforms/visibility; bone poses and rig IK/limits override their procedural poses. Colors are isolated by semantic object/part. Camera fields are independently compared with the baseline, so changing focal length preserves its camera movement. Background, exposure and registered/new lights are shared with export. Existing objects/parts are editable; arbitrary model import or new actor types in a code scene require a new runtime asset adapter and are intentionally blocked by the UI/gateway.

The scene program owns its thirty named action recipes. It does not pretend these are imported skeletal AnimationClips. Ordinary StudioScene GLB/clip editing remains a separate existing path. GLB transform baking does not preserve all animated material/light/rain behavior of this runtime; Three/Remotion are the faithful export paths for these programs.

Verification: `npx tsx --test tests/code-scene.test.ts` from `web` runs random-seek state equivalence, all-frame finite poses and hand targets, strict schema, compiler IDs, true panel removal/repair, seed ownership, isolated part edits, director IK/light integration and focal-length-only edits. Fresh authored-program numerical evidence and representative actual renders live in `output/code-films-20261002/runtime-qa/`. Wrist-target error is a contact anchor check, not a complete mesh collision/fingertip intersection proof. Full motion/video acceptance belongs to the subsequent stress and final-media stages.
