# Studio v3 backend

The existing Node gateway owns v3 project state. Next.js is an authenticated BFF; it must forward `VIDEO_API_TOKEN` server-side. Every `/api/v3/*` route, including assets and script HTML, requires this bearer token. The token is an installation capability; trusted BFF visitor UUIDs add project/asset/job ownership for browser requests. Internal bearer calls without a visitor retain legacy access. See [CODE_TASKS.md](CODE_TASKS.md) for the new anonymous boundary and persistent scene/render/NR contracts. Existing v1 routes are unchanged.

Requires Node 22.13+ with `node:sqlite`. One gateway process owns one `STUDIO_DATA_DIR`. Production uses the Docker named volume `ai-video-studio-data` mounted at `/data/studio`; do not place the active SQLite database on a NAS/SMB/Synology-synchronized directory. Keep the DB, WAL and immutable `assets/` together when taking a consistent backup. For a live backup use the SQLite backup API, or stop the gateway before copying the directory.

SQLite stores project snapshots, command receipts, undo/redo history, asset ownership, task input snapshots and accepted provider IDs. Writes use transactions with optimistic project revision checks. User edits can be undone; newly uploaded assets and finished provider work remain available when undoing authoring changes. `PUT` rejects forged assets, takes and approval records. Media are immutable, named by SHA-256 and served with single-range support. This version intentionally has no automatic media deletion.

`GET /api/v3/projects/:id/review` returns `{data:{html,shots:[{shotId,hash}]}}`. The HTML embeds reference image bytes and includes frame intervals and SHA-256 approval hashes. `GET .../script` returns the same standalone HTML; `?format=json` returns the review envelope. Hashes include shot content, scene, animation and referenced asset hashes; canvas position and revision counters are excluded. Changes invalidate old approvals. Generations require an approved hash and a first reference frame. OpenAI-compatible video providers use only the first frame; native Gemini supports first and last frames. Receipts state the actual mode. Provider output is checked with ffprobe; short videos fail rather than being stretched.

Tasks are committed before network submission. Submission is one attempt, without model fallback. A provider ID is persisted as soon as accepted. Restarts resume polling accepted IDs; interruption during an unconfirmed submission yields `uncertain` and never resubmits automatically. An uncertain task reserves that identical input against another automatic submission. Check the upstream record manually before any further generation. `failed` means explicit rejection or execution failure; it is not proof that an upstream job was free. Local exports can safely rerun after restart. Blender requests use the durable gateway job ID as `jobRef`, and the worker deduplicates that ID and input hash.

Seedance 2.0 requests are floored to its documented 4-second minimum; the provider's 15-second limit and Studio's stricter 12-second single-shot limit are both enforced before any external POST. Source timeline frames remain unchanged and the sequence trims the resulting footage. Other OpenAI-compatible models keep their existing 2-second minimum, while native Veo keeps 4/6/8-second durations. Before submission, a credential-free receipt records the exact prompt, model, reference hashes, timing/aspect parameters and SHA-256 of the actual JSON request body; failure to persist that receipt prevents the POST. Failed/uncertain tasks retain the receipt. Requested frames, provider duration and ffprobe-measured output duration are distinct. A duration-contract code update never retries existing failed jobs, and the same idempotency key still returns the original failure.

SQLite schema version 2 adds durable job receipts: when concurrent equivalent requests have different idempotency keys, every key remains bound to the original task after completion and restart. Only a genuinely new key submitted after completion can request a new take. Accepted operations with exhausted polling/download retries or changed provider configuration become `uncertain`; their provider IDs are retained and identical input remains reserved. A short, decoded output can still fail explicitly.

Export idempotency compares the actual render plan: project identity/name, fps/aspect, sequence and referenced asset identities/content hashes. Server revision/timestamps, unrelated assets and newly appended output do not change that plan. Original frozen snapshots and `sourceRevision` remain unchanged; existing schema-2 full-snapshot receipts and active-job aliases remain readable. Reusing a key after changing rendering inputs still returns 409.

Downloads, including a completed result recovered from SQLite, revalidate the original provider base URL and backend before using credentials. A completed generation always remains available as a take, but it is auto-selected only if the current shot still has the submitted approval hash and no take has been selected. Later authoring and explicit selections are preserved.

AI receives typed scene operations and optional storyboard arrays, and cannot execute code. Patches are validated atomically, respect locked objects and scene selections, and enter the undo history. Storyboard scope accepts `{shots?,nodes?,edges?}`; existing take/approval records remain server-owned. LLM configuration prefers `AGENT_LLM_BASE_URL/API_KEY/MODELS` and then the existing image relay chat configuration; `STUDIO_LLM_MODEL` can select a specific configured model.

Dynamic AI accepts only `track.set` at the requested current frame. An existing track keeps its target, property, settings and all other keys; a new track contains exactly one key at that frame. Direct user animation editing can still create and manage full motion clips. Generation receipts expose only actual submitted prompt, reference asset IDs/hashes/roles, ignored references and timing/aspect parameters. `requestedModel` is separate from `model`; an upstream that does not report an actual model produces `model: "unreported"` and `modelReported: false`, never an invented confirmation.

Model uploads parse the GLB 2.0 JSON and overwrite caller-supplied part metadata. Mesh nodes have `gltf-node-N` IDs, `/nodes/N` source pointers, and their nearest mesh ancestor ID. `SceneObject.parts` can reference only those verified nodes. `part.update` respects object/part locks; `AnimationTrack.partId` permits only position/rotation/scale/visibility and cannot be combined with a bone. AI `partSelection` permits only the exact selected parts, rejecting whole-object, scene and storyboard changes. Dynamic mode also rejects storyboard replacement. Optional canvas `viewport` is finite and zoom is bounded to 0.15–2; it does not affect shot approval hashes.

Blender v3 is considered available only after its `/api/v3/capabilities` endpoint confirms support. `STUDIO_WORKER_TOKEN`, when set, protects that transport. Preview video, sampled frames and landmark validation results are copied into immutable gateway assets. FFmpeg, ffprobe, Python 3, Pillow and a CJK font are installed in the gateway image for deterministic composition. Text/audio/video composition is executed locally by `compositor.mjs`, not by an additional service.

Both accepted and polled worker receipts must match the submitted `jobRef` and `inputHash`. Before any preview media is downloaded, the entire completed receipt must match the requested frame count, fps and resolution; image/landmark frames must be inside the requested end-exclusive range, and media URLs must belong to that job's worker asset path. A mismatch fails the preview without attaching foreign media or stamping it with a locally supplied hash.

Legacy import creates a new project and copies media only from configured `legacyAssetOrigins` (public v1/image origins). It never trusts legacy local filesystem paths or overwrites source files. Legacy metadata and any unavailable media are retained as readable canvas notes. Old approvals do not carry over.

Subject cards bind an identity image (`assetId`), an optional imported GLB (`modelAssetId`) and a scene object (`sceneId`, `objectId`). Review hashes include identity/model content when that object appears in the shot's `subjectIds`; the standalone HTML embeds the corresponding identity images. Removing an object clears card bindings.

When `VIDEO_STORAGE_BASE_URL` and `VIDEO_STORAGE_TOKEN` are configured, completed generated clips and final exports enter a separate durable NAS archive phase. The existing upload API deduplicates `source_task_id` plus `kind=studio-v3-video`. An interrupted archive resumes with the same task ID; up to three transient upload attempts are allowed. The job remains locally complete if NAS is unavailable, and `output.archive` states `pending`, `running`, `complete`, `failed` or `unconfigured`. Blender preview fixtures are never auto-archived. Remove storage variables from isolated validation processes to avoid archiving test outputs.

An archive is marked complete only when its receipt has a durable string ID, the submitted task ID/kind, exact local byte length and matching `metadata.assetHash`. This validates receipt consistency; metadata is not proof of NAS file bytes. Production archive acceptance still requires downloading the stored file and comparing its SHA-256. Mismatched receipts consume the bounded archive retries and preserve the local output.

Image build context must contain `node-gateway.mjs`, `studio/` and `config.toml` when using `gateway/ops/Dockerfile`. Historical production migration scripts are excluded from this public snapshot; configure local volumes and environment explicitly when deploying. No deployment or paid provider generation is performed by the test suite.

Run:

```sh
node --test gateway/studio/*.test.mjs
```

`gateway/ops/test-studio-persistence.ps1 -FixtureDirectory <copied-gateway-directory>` creates two sequential, network-disabled Node containers with the same dedicated volume and different container IDs. It proves SQLite/project/history/assets/provider handles survive container replacement, checks authenticated Range access, and then removes only its own random fixture resources. The fixture directory needs `studio/*.mjs`, not production environment files. `-Image` can explicitly select an existing local Node 22 image; the default reads only the current gateway's image ID. `-EvidencePath` saves the small JSON receipt.

For image acceptance, package `node-gateway.mjs`, `studio/*.mjs`, `ops/Dockerfile`, both `ops/test-studio-*.ps1` scripts, and a credential-free `config.toml` containing only `openai_model_name`. Run `ops/test-studio-image.ps1 -FixtureDirectory <package> -EvidenceDirectory <existing-output-directory>`. It builds a unique test image, starts the baked gateway with no network and a dedicated volume, verifies FFmpeg/ffprobe/Pillow/CJK rendering and source hashes, and runs schema 2 container replacement including durable duplicate-job receipts. It preserves the build log and image, removes only its own test containers/volumes, and never replaces a production service.
